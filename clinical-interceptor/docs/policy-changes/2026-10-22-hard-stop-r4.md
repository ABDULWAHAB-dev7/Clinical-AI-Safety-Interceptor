# Policy change: hard-stop R4 is enforced on the request path (2026-10-22)

Status: implemented. Clinical review: **none assigned**. This follows ARCHITECTURE 7.2 and the README, which list R4
as a hard-stop rule that cannot be disabled by configuration.

## What changed

A document that yields no claims is blocked. `api/engine.py` `audit()` sets `pipeline_status` to `BLOCKED` when the claim
list is empty, and stores `hard_stop_rules: ["R4_no_assertions"]` in the report payload.

- Before: a note with no checkable statement (for example `"..."`) was `VERIFIED` and delivered as clean.
- After: it is `BLOCKED`, `/v1/verify` returns `HARD_BLOCK`, `delivered: false`, no spans, and `rules_fired` contains
  `R4_no_assertions`.

## Why

An empty result is the absence of evidence, not a clean verdict. The system fails closed, and a document that was never
checked must not be released as if it had been.

## What did not change

- R1 (pipeline or audit error) and R2 (verification error) already refuse the request through exceptions.
- R3 ("any contradicted claim blocks") is **not** enforced as written. The policy record
  `2026-10-20-nli-critical-threshold.md` and `2026-10-21-negation-nli-scope.md` define when a contradiction blocks.
- `core/policy.py` `decide()` is still not called by the request path. R4 is enforced in the engine, where the claim
  count is known.
